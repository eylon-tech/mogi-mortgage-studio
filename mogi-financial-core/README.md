# Mogi Financial Core — בסיס נתונים ומנוע תזרים

גרסה 0.2, עודכנה ב־8 באוקטובר 2026. זהו שירות מקומי נפרד לאיסוף היסטוריה, תיעוד מקורות וחישוב תזרים. הוא אינו מחליף כרגע את מנוע האתר הקיים. נוספו מנוע מחקר לחיזוי ריביות שוק, תמהיל רב־מסלולי ומדד בפועל. חיזוי ריבית אישית ואופטימיזציית תמהיל אינם מופעלים בו.

המאגר מכיל **248,553 רשומות פעילות ב־333 סדרות, משבעה מקורות בנק ישראל ומקור הלמ״ס**. 569 רשומות כוללות ערך חסר במקור ונשמרות כ־NULL. המספר הכולל כולל נקודות עתידיות בעקומי התחזית; אין לפרש אותו כמספר עסקאות או הצעות לקוח.

## מעבדת חיזוי הריבית שנבנתה כעת

[דוח אינטראקטיבי](reports/rate-backtest.html) · [יומן 488 תחזיות](reports/rate-predictions.csv) · [פרוטוקול הניסוי](research/forecast/protocol.json) · [קוד המנוע](research/forecast/backtest.py).

נבדקו 182 חודשים לכל אחת משתי סדרות ריבית קבועה, מיולי 2011 עד אוגוסט 2026. קודי הסדרות הם `BNK_99034_LR_BIR_MRTG_467` ו־`BNK_99034_LR_BIR_MRTG_1492`. המטא־דאטה הרשמי אומת: הלוואות חדשות למטרת מגורים, ריבית קבועה וממוצע כולל; לא אשראי צרכני בביטחון דירה, לא ריבית עוגן לבדה ולא קבוצת בולט/בלון. [מיפוי ואסמכתה](research/forecast/metadata-verification.json).

בכל אחד משישה שילובי מסלול ואופק נבחנו **74 תצורות**: ריבית קודמת, מגמה מרוסנת, ו־Ridge עם ארבע קבוצות משתנים, שלושה חלונות אימון, שלוש עוצמות רגולריזציה ושני משקלי שילוב עם הבסיס. משתני המאקרו כוללים ריבית בנק ישראל, עקום אג״ח נומינלי וריאלי, ציפיות אינפלציה ומדד בפועל. האימון והנרמול מוגבלים לעבר; רק תוצאה שכבר הבשילה לפי השהיית הפרסום יכולה לשמש באימון או בכיוונון. חסרים אינם מושלמים.

נקודת בסיס = 0.01 נקודת אחוז. אין כאן מדד ״אחוז דיוק״ כללי. נבדקו גם RMSE, הטיה, שגיאה בזנב, כיוון השינוי, כיסוי ורוחב טווחים, ביצועים לפי שנה ודגימת בלוקים לתלות בזמן. בבדיקה עם השהיית פרסום נוספת חלק מהתוצאות משתנות באופן מהותי; אין יתרון יציב שמצדיק חיבור אוטומטי לייצור.

**מצב הנתונים:** קובצי העבר הורדו כיום ויכולים להכיל תיקונים רטרואקטיביים. ההשהיה הראשית — חודשיים למשכנתאות וחודש למאקרו — היא הנחת מחקר, לא תאריך פרסום היסטורי מאומת. בדיקת הרגישות משתמשת בשלושה ושני חודשים בהתאמה. זו בדיקת latest-vintage עם מגבלות זמן, ולא מאגר point-in-time מוכח; `pointInTimeVerified=false`. פלט המחקר אינו עוקף את מדיניות `asOf` של המאגר התפעולי. מוסכמת הריבית של סדרות BIR נשארת `source_unspecified`, ולכן אין הזנה אוטומטית שלהן לחישובי ריבית נומינלית/אפקטיבית.

אין להסיק סיבתיות ממקדמי המודל. ממוצע השוק משתנה גם עם הרכב העסקאות. אין מדידת חיזוי אישי ללא הצעות אמת. 25 חודשי קו המשווה אינם מספיקים לפרוטוקול הזה, ולכן לא הופק ציון דיוק לפי בנק. תקופת המבחן הנוכחית נחשפה; שינויי מודל עתידיים צריכים מבחן חדש או מעקב קדימה.

הניסוי נשמר בטבלת `rate_backtest_run` שאינה ניתנת לעריכה, עם חתימות הקוד, הנתונים, הפרוטוקול והתוצאות. אין חיבור מהמחקר לאופטימייזר. הנתונים שנכנסו לניסוי נשמרו בעותק בעל SHA-256 ב־`research/forecast/data`, והתחזיות המלאות והסבר התרומות במודל נמצאים תחת `research/forecast/runs`.

לשחזור על אותה גרסת נתונים (Python 3.11 ומעלה):

```sh
.venv/bin/pip install -r requirements-research.txt
OPENBLAS_NUM_THREADS=1 .venv/bin/python research/forecast/backtest.py
npm run research:save
# יצירת הדוח דורשת בנוסף matplotlib 3.10.8
.venv/bin/pip install matplotlib==3.10.8
.venv/bin/python research/forecast/render_report.py
```

`npm run research:export` מייצא גרסה חדשה מהמאגר; אין להריץ אותו כדי לשחזר ניסוי ישן. בעת ייצוא/ETL/שמירת מחקר עם PGlite מקומי יש לעצור קודם את שירות ה־API: מסד זה פתוח בתהליך יחיד בלבד. `DATABASE_URL` מאפשר PostgreSQL חיצוני, שהפעלתו טרם נבדקה כאן. הדוח מוגש ב־`http://127.0.0.1:4318/research/rates` לאחר הפעלת השירות; ה־API למחקר הוא `GET /v1/research/rate-backtests/latest`.

## עובדה, תחזית ומועד זמינות

`value_class=observed` מציין נתון שפורסם על תופעה שנצפתה. גם ממוצע שוק כזה אינו הריבית של לקוח מסוים. `market_model` מציין ערך שפורסם מתוך מודל שוק; בפרט, מדד 451 אינו מדד המחירים שהתרחש בפועל.

לכל תצפית נשמרים:

| שדה | משמעות |
|---|---|
| period | תקופת התצפית או חודש העקום; אינה תאריך הפרסום |
| horizon_months | אופק התחזית; ‎-1 לתצפית ללא אופק, 0 לנקודת הבסיס של המדד |
| effective_from | תאריך תחולה מפורש בטבלאות פירעון מוקדם, אם קיים |
| source_reported_date | תאריך שמופיע בקובץ עצמו; אינו מוכרז אוטומטית כמועד פרסום |
| published_at | מועד פרסום מוכח; נשאר NULL בקליטה זו |
| fetched_at / ingested_at | מתי העותק נתפס ומתי הושלמה קליטתו |
| document_id / sha256 | הגרסה וקובץ המקור המדויקים |
| source_locator | גיליון ותא ב־Excel, או שורה ועמודה ב־CSV |
| value / status / raw_value | ערך עשרוני, מצב present/missing/invalid והייצוג המקורי |
| unit / unit_multiplier | יחידה וחזקת עשר מקוריות; למשל ILS עם מכפיל 3 אינו שקלים בודדים |

שאילתת asOf מחזירה רק גרסה שנלכדה **וגם נקלטה** לפני המועד המבוקש. נבחרת הגרסה השלמה האחרונה של המקור. בקו המשווה בלבד נשמרים גם חודשים שכבר נלכדו ושנמצאים מחוץ לחלון התקופות של הגרסה החדשה; בתוך חלון חדש הגרסה החדשה מחליפה את הקודמת. תא שנמחק או הפך לחסר אינו מתמלא בשקט מגרסה קודמת. נתונים היסטוריים שהורדו היום אינם זמינים אוטומטית לבדיקת מודל כאילו היו ידועים בשנת 2020.

בנק ישראל מתעד החלפה של עקומים היסטוריים בעת שינוי המודל ב־2022. לכן אפשר לחשב היום תרחישים לפי ההיסטוריה שפורסמה בעותק הנוכחי; **אי אפשר עדיין לטעון שזהו מאגר מלא של המידע שהיה ידוע בכל תאריך בעבר**. אסמכתה: [מתודולוגיית עקומי 451](https://www.boi.org.il/boi_files/Statistics/Estimation%20of%20yields%20from%20government%20bonds.pdf).

גרסאות מקור ותצפיות אינן ניתנות לעדכון או למחיקה דרך פעולות SQL רגילות. שינוי נקלט כגרסה חדשה. שינוי בממדי הסדרה או ביחידות עוצר את הקליטה ודורש טיפול מפורש במיפוי. מספר גרסת הקורא נשמר בכל ריצת קליטה. קליטת קובץ חוזרת היא idempotent; חזרה של המקור לתוכן ישן נשמרת כפרסום שנלכד מחדש.

## מיפוי והסתייגויות המקור

- קו המשווה: L01 הוא ריביות, L02 הוא הרכב המסלולים. B הוא חודש; שורה 10 מזהה בנק ושורה 12 מזהה מסלול. IRR נשמר בנפרד מריבית המסלול. לפי עמוד קו המשווה הרשמי הריביות שנתיות אפקטיביות; תיקון זה נקלט בגרסת קורא 1.1.0 בלי לשנות את הרשומות הישנות. חסרה כאן ההיסטוריה 03.2023–07.2024, והיא לא הושלמה בסינתזה.
- עקומי 451: A/B/C הם שנה, חודש וסוג ממוצע. שורה 5 מגדירה אופק בחודשים. נקודות התשואה מתחילות ב־1 והמדד ב־0. שלושת הגיליונות חייבים להתאים לפי חודש וסוג ממוצע.
- XLS הישן: נקרא לפי תוכנו ולא לפי הסיומת. גיליונות מחשבון אינם מקור נתונים. תא שגיאת Excel אינו המספר של קוד השגיאה.
- ריביות פירעון מוקדם: נשמר תאריך הדיווח המדויק, כולל פרסומים חצי־חודשיים. ב־RESULT_OLD!H174 חסר תאריך התחולה של הדיווח מ־31.10.2002; הוא נשאר NULL ונרשמת בעיית איכות. שינויי מדרגות וגבולות לפני נובמבר 2002 נשמרים במשטר נפרד. [הסבר רשמי על תדירות, ריבית אפקטיבית וגבולות התקופות](https://www.boi.org.il/information/interestrates/mortgage/).
- BIR: קודי LTV ו־PTI בקובץ נשמרים כממדים, אך אינם הופכים לטבלת מחיר של לקוח. הסדרות המצרפיות אינן תחליף לתוויות של הצעות אמיתיות.

## חוזה מנוע התזרים

מסלול יחיד מחושב ב־`/v1/simulations`. גרסה 0.2 מוסיפה `/v1/bundles`: סכימת תזרימי מסלולים שונים, כולל תקופות שונות, ו־IRR של התזרים המצורף במקום ממוצע ריביות. החזר בתנאים הנוכחיים, תחזית והחזר לצורך יחס החזר מוצגים בנפרד. חוסר בתחזית למסלול משאיר את ההחזר הנוכחי זמין, אך מונע תחזית כוללת חלקית ומטעה. גרייס נמדד ביחס החזר לפי התשלום לאחריו; בלון מציג בנפרד ריבית חודשית ותשלום סיום.

`/v1/regulation/rules` מציג את חבילת הכללים המקומית מ־[הוראה 329, גרסת יוני 2026](https://www.boi.org.il/media/hjrlkrse/h2852.pdf), עם תחולה שנבדקה ל־1–8 באוקטובר 2026 בלבד. נבדקים שיעור מסלולים משתנים, LTV מצטבר, PTI ותקופה. הכנסות מוכרות ומחויבויות מפורטות, לרבות החוב הקיים על אותו נכס, עם מניעת ניכוי כפול. חריגים, מידע חסר או תאריך אחר מסומנים לבדיקה. `passes_baseline` אינו אישור בנק. מנוע האופטימיזציה עדיין מנותק.

כסף וריביות עוברים ב־API כמחרוזות עשרוניות. `4.5` פירושו 4.5 אחוז לשנה. הקרן והעמלות חייבות להיות באגורות שלמות. אין ברירת מחדל שקטה בין ריבית נומינלית לאפקטיבית:

- נומינלית: ריבית חודשית = ריבית שנתית / 12.
- אפקטיבית: ריבית חודשית = ‎(1 + ריבית שנתית)^(1/12) − 1.
- שפיצר: ‎PMT = P·r / [1 − (1+r)^(-n)]; באפס ריבית משתמשים ב־P/n.

החישוב משתמש בדיוק פנימי של 40 ספרות. רישומי הכסף החודשיים מעוגלים לאגורה, half-up. התאמת האגורות הסופית נסגרת בתשלום האחרון. זו מדיניות מפורשת שנבדקה; התאמה ללוח של בנק מסוים עדיין דורשת לבדוק את מוסכמות הבנק.

סדר הפעולות החודשי הוא שינוי ריבית במועד שנמסר; הצמדת יתרת הקרן; צבירת ריבית; תשלום או היוון במהלך גרייס; תשלום הקרן המתוכנן; פירעון מוקדם ועמלה מפורשת. כל שורה מקיימת בדיוק:

`יתרה בסוף = יתרה בתחילה + הצמדה + ריבית שהוונה − קרן בתשלום − פירעון נוסף`

נתמכים שפיצר, קרן שווה, ריבית בלבד עם קרן בסיום ובלון מהוון; גרייס חלקי/מלא במסלולים הנפרעים; שינויי ריבית בחודשים מפורשים; מסלול מדדים מלא עם רצפת בסיס או ללא רצפה; ופירעון מוקדם שמקטין החזר או מקצר שפיצר. בעת שינוי ריבית מתבצע חישוב מחדש לפי יתרת התקופה החוזית המקורית. זהו הכלל המפורש לגרסה זו, גם לאחר בחירה בקיצור תקופה.

חסרה נקודה במסלול המדד? הבקשה נדחית. תרחיש בנק ישראל חסר במועד asOf? מוחזרת שגיאה 422. אין הארכת עקום, מעבר אוטומטי לתחזית שטוחה או החלפת תא חסר באפס. עקום שנבחר לסימולציה נשמר באמצעות מזהי התצפיות וקובץ המקור.

IRR מחושב על משיכה חיובית בזמן 0 ותשלומים שליליים בהמשך, לאחר עמלה ראשונית. מוחזרים IRR חודשי ושנתי אפקטיבי. NPV מוצג מנקודת המבט של הלווה לפי שיעור היוון שנתי אפקטיבי מפורש. תזרימים עם שינויי סימן נוספים אינם נתמכים כדי לא להציג שורש IRR שרירותי.

**גבולות הגרסה:** תקופות חודשיות שוות בלבד; אין ימים בפועל, תקופת ביניים, לוח חגים, משיכות בנייה מדורגות או חישוב אוטומטי של עמלת היוון חוקית. עמלות מתקבלות כקלט מפורש. מדד בפועל מהלמ״ס חובר באמצעות `cbsRealizedIndex`: מסלול חודשי מפורש בבסיס אחיד שהלמ״ס עצמה מפרסמת. קובצי העמודים, חתימותיהם, מקדמי הבסיס ומיקומי הנתונים נשמרים. זו הרצה היסטורית לפי חודשי תצפית, לא מוסכמת ״מדד ידוע״ של בנק; תאריכי הפרסום המקוריים אינם מאומתים. מסלול שחסר בו חודש נדחה ולא הופך לתחזית.

השוואת התזרים הקבוע להרצות המחשבונים שנשמרו קודם לכן נמצאת ב־[דוח התאמה](reports/bank-parity-v02.json). הפער בסכום הכולל הוא אגורה מול הפועלים, 18 אגורות מול ירושלים/הבינלאומי ו־2.26 ₪ מול דיסקונט/מרכנתיל. נבדקו גם 300 שורות מ־Wise ומירושלים. זה אינו אישור התאמה בנקאי: הבדלי עיגול ותשלום השיא בדיסקונט/מרכנתיל עוד דורשים בירור, ואין לוח מאושר של לקוח אמיתי. אין כאן מדידת דיוק של חיזוי ריביות אישיות.

## הפעלה ושחזור

דרישות: Node 22.13 ומעלה, Python 3.10 ומעלה, curl. תיקיית data/pg המקומית כבר נוצרה ונטענה באמצעות **PGlite — PostgreSQL משובץ**. זה אינו שרת PostgreSQL בענן. אותה סכמת SQL ומתאם pg הוכנו לשרת PostgreSQL 15 ומעלה באמצעות DATABASE_URL; מסלול השרת החיצוני טרם נבדק מול שרת פעיל.

```sh
npm ci
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
npm start
```

לשחזור מהמקורות שכבר נשמרו, בלי להוריד גרסה חדשה:

```sh
.venv/bin/python scripts/normalize.py
npm run db:ingest
npm run report
```

להורדה חדשה וקליטה, לפי בקשה בלבד — לא נוצרה משימה מתוזמנת:

```sh
MOGI_PYTHON=.venv/bin/python npm run data:refresh
```

לשימוש במסד PostgreSQL שהוקם בנפרד, הגדירו DATABASE_URL בסביבת התהליך, ואז הריצו db:ingest ו־start. קובץ .env אינו נטען אוטומטית. אין לשתף סיסמה או להכניסה לקוד. נדרש גיבוי גם למסד וגם לארכיון הקבצים. ריצת ETL אחת בכל פעם היא מגבלת שירות הקליטה הראשון.

```sh
curl http://127.0.0.1:4318/v1/coverage
curl -H 'Content-Type: application/json' --data-binary @examples/fixed.json http://127.0.0.1:4318/v1/simulations
```

בדיקות:

```sh
npm test
.venv/bin/python -m unittest discover -s tests -p 'test_*.py'
npm run contracts:build
```

הבדיקות מכסות ערכי ייחוס עצמאיים, איזון כל שורת תזרים, גרייס, בלון, הצמדה, פירעונות, IRR/NPV, שינויי כותרות בקובצי מקור, גרסאות, קליטה חוזרת, כשל אטומי, הפרדת חסר מאפס, מניעת מידע עתידי ושחזור תרחיש עם ראיות. תוצאות הריצה נשמרו ב־[בדיקות Node](reports/node-tests-v02.txt) וב־[בדיקות Python ומניעת דליפה](reports/python-tests-v02.txt).

## שערי ההמשך לפני חיבור חיזוי אישי

1. להשלים את ההיסטוריה החסרה של קו המשווה ממקור מתועד, ולאמת תאריכי פרסום מקוריים למדד ולסדרות המאקרו. המדד ובסיסיו כבר נקלטו.
2. לאמת מוסכמות חודש/יום, הצמדה ועיגול מול לוחות בנקאיים אמיתיים; להרחיב לעמלות חוקיות. תזרים רב־מסלולי כבר קיים.
3. להרחיב את חבילת הכללים המתוארכת שכבר נוספה לטיפול מאומת בחריגים ובתאריכים נוספים לפני חיפוש תמהיל.
4. לקלוט הצעות אמת כמכלול מסלולים ובנק, עם נתוני עסקה ולווה, תאריך, מקור ושלב ההצעה; לשמור אותן מחוץ לטבלאות נתוני השוק.
5. לבחון חיזוי אישי בחתך זמן ובניתוק בין לווים, מול baseline, באמצעות MAE בנקודות בסיס, שגיאה לפי בנק/מסלול/קבוצת סיכון וכיסוי טווחי החיזוי. רק לאחר תוצאות מספקות לחבר את טווחי הריבית לאופטימיזציה.

המנוע הנוכחי נותן בסיס מתמטי וראיות שניתן לבדוק. הוא אינו מציג מינימום IRR/NPV כאלגוריתם לחיזוי מחיר של לקוח.

לשחזור כל עותקי המקור שנשמרו לאורך זמן למסד חדש: `MOGI_PYTHON=.venv/bin/python sh scripts/rebuild-history.sh`. שחזור זה שומר את מועדי לכידת הקבצים, אך מועד הקליטה למסד החדש יהיה מועד השחזור; לשימור מדויק של היסטוריית זמינות המערכת יש לשחזר גיבוי של המסד עצמו.
